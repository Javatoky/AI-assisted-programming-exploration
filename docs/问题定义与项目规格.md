# 重要-紧急四象限事务判定助手 —— 问题定义与项目规格

> 本文档描述用户的相关需求与此项目解决的问题

## 用户画像
大三CS专业学生，看重自身各方面的成长，希望自己不断进步成为一个卓越的人才

当前的大学阶段主要注重专业学习与认知提升方面的发展，其他方面(身心健康、社交与友谊、体验与乐趣)维持在基础线
- 在专业方面，目前对大模型领域感兴趣，当前个人发展方向为大模型应用，但这只是暂定目标
- 认知方面，用户有写元思考日志的习惯，能够从中发现自己的思维漏洞。

看重课业成绩，因为这能反映自己是否具备自学能力和持续学习的能力，这对未来能作为人才被选举有一定作用

## 问题描述
用户现在面临着一个耗费精力与决策能力的问题: 事项的优先级判定问题。
用户采用重要-紧急四象限判定方法，将事项分为四类:重要且紧急、重要不紧急、不重要但紧急、不重要不紧急
这虽然是一个比较好的决策方法，理清了用户的决策思路，但在实际应用过程中，用户发现这会让自己在一天中耗费掉判断事项是否重要、是否紧急的时间，并且用户会在一些难以判断事项上耗费大量精力去决策
判断事项优先级对于用户来说比较重要，它能理清事项处理顺序，但是这对于用户的发展方向没有直接的作用，用户渴望一个工具来代替做好决策，节省精力集中到处理这些事务本身上

## 功能需求
- 主要的功能: 能根据用户输入的多个事项以及附属信息，给出用户其所判断每个事项所属的象限，不需要在象限内给事项排序，只需要分类，而工具的判断原则要符合用户实际的决策标准
- 其他功能: 暂时无

## MVP验收标准
1. 主要功能有完整源码实现，且源码能够从头到尾跑通，可以没有前端界面，后端至少能在终端中跑通
2. 必须收集至少50个来源于用户的真实事务以及用户最终所判定的象限形成一份集成测试集，其中必须有至少15个让用户感到犹豫的事务，主要功能的源码实现能够通过集成测试集(至少50个测试用例)，通过率至少90%

## 项目规格
> 包括项目的输入、输出与内部规则
### 输入
至少包括下面的字段
```
transaction: str
deadline: date
```
事务描述决定重要性，截止时间与当前时间决定紧急性
### 输出
至少包括下面的字段
```
quadrant: int
reason: str
```
quadrant是用户想要的象限结果，reason既能让用户判断是否认同模型结论，又能作为开发所用的判断模型理解是否正确的标准
reason是1-2句话
