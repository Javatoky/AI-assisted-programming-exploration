# 定规格
## 总体功能需求
能根据用户输入的多个事项以及附属信息，给出用户其所判断每个事项所属的象限，而工具的判断原则要符合用户实际的决策标准

## 输入锚定
假设我们已经有了这个助手，那么我们希望给他一个事务，他就帮我们分类好这个事务所属的象限
所以输入至少有事务的描述，想一想我们怎么描述一个事务？
一个事务的描述的最简形式应该是至少包含一个动词的短语, 例如
"完成深度学习`project1`作业"
"背15个法语单词"
"推进`大模型核心应用`project的进度"
"去学院开会"
这是用户本身使用四象限对事务描述的做法，像这样的动词短语，其很精确的就能描述一个任务，因为用户的主语可以省略，从语法角度来说就只需用陈述句加上动词和关键名词，就能详尽的描述一个任务
这样的一个陈述句中，什么是比较重要的呢？动词你会发现面对不同的名词会有很多中选择，比方说'写'作业和'完成'作业还有'提交'作业，动词能表示做这个事的方式，但是做这个事务的方式还是要看是什么事务。
所以名词很关键，名词的描述很重要，它反映了用户从什么角度看这个事项，而且也能反映这个是事项的重要程度。不能简简单单写一个"写作业"，写什么科目的作业，至少要描述清楚，这可能影响工具对事务重要性的判定，比方说我写一个重要的专业课作业和写一个与专业无关的水课作业他们的重要程度是不同的，所以会发现对名词的描述本身就很能影响重要性的判定，用户本身自己写在记事本上不会觉得有什么对这个事项的遗漏，因为用户本身他们内心清晰知道这指的是什么事，但是机器不会察觉你表述中有什么遗漏，所以关键在于，用户必须把事务的名词相关描述表达的足够清楚，没有心里知道但表述没有的这种遗漏，用户才能传达清楚，机器才明白是什么意思，才能更好的对事务的重要性进行分类
所以这是一个重要的点，描述本身的准确性，对于重要性判定有很大影响，这个暂时搁置
这样就足够了吗？我们来看看这些任务还有没有什么必要的输出？
首先，有些事务是有截止时间的，有些没有，再来思考一下，截止时间是否会对事务划分有影响？一定有的，因为截止时间就是判定事务是否紧急的重要标准，所以截止时间这个字段是一定要有的
思考一下，紧急本身还有其他判定方式吗？
紧急这个方面，其实就是一个事务距离截止时间，或者这个事务必须要完成的时间越少，越紧急; 用户是一名学生，其大部分在学校的课程作业和事项都有截止日期，所以当前时间与截止时间的一个差值应该是一个紧急的判断标准
让我们再想想，一个事务，如果说它本身要很长时间完成，比方说3天，那如果说工具把紧急的事项当作1天以内的剩余完成时间的事项，这样本身也是不合理的，所以说考量一个事务是否是紧急的，还需要其大概需要花费的时间，而且这个时间得往多估计
紧急应该还有其他更复杂的情况去判定，比如说，我们小组要完成一个工程，这个工程还有一个月截止，时间总体充裕，但我是这个工程的组长，前置工作要我完成其他组员才能动工，那这个在情况下，判定是否是紧急的就很复杂

所以，根据上面的分析，我们就先暂时不考虑更复杂的情况，假设用户真的能够写好一个事务的表述(没有藏起来的细节)，不存在需要超过一天才能完成的事务，用户本身也估计好了前置工作的截止时间，那么我认为，输入至少是如下的方案:
```
transaction: str
deadline: date
```
很简单的两个字段，transaction内部信息确定重要性，deadline与当前时间确定紧急性，我认为这两个输入字段是最小的最必要的输入字段

## 输出锚定
下面讨论输出字段，站在用户的视角，用户最后想要的是什么？
应该是事务所属象限才对，这也是用户(我)在进行决策工作后所得的内容，所以这个"象限"字段是必须有的
那么根据我的习惯，重要且紧急是象限1，重要不紧急是象限2，不重要不紧急是象限3，不重要但紧急是象限4，只需要给出对应序号即可
象限足够了吗？
还不够，用户是我，我是一个强调自主权的人，也是最后审视AI输出的人，单单输出象限是不够的，AI不提供理由，我也没办法做出认同，而且也有可能听从了AI的错误判断，AI要给出判定的理由，呈现给我，我才能审视它对不对，才能避免错误的情况，而且同样这也可以作为一种测试手段，看看AI的思路是否是对的，有没有"过拟合"样例集
因此，输出字段也还至少要包括划分理由，1-2句就可以了
现在，输出字段够了吗？
我已经从用户和开发者角度考虑了这个输出，用户角度希望给出划分结果，而开发者角度还希望得到划分理由
我暂时想不到其他的应有的字段了，我觉得这些目前足够了
所以输出字段应该有
```
quadrant: int
reason: str
```

好，那么现在最小的输入与输出规格已经确定，后续遇到实际问题再做考量和决策
